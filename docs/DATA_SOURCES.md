# データソース調査メモ

神奈川県内のプロ・トップリーグチームについて、試合日程をどこから取得できるかを
GitHub Actions上で実際にアクセスして調べた結果
(`.github/workflows/inspect-sources.yml` / `scripts/inspect-sources.mjs`)。

判定は「初期HTML(JavaScript実行前)に日付パターンがいくつ含まれるか」で行っている。
サーバー側で日程が描画されていれば、fetchだけで取得できる。

- ◎ = 日付15件以上。シーズンまたは月単位の一覧が載っている
- ○ = 日付5〜14件。直近数試合のみの可能性があり、別ページの調査が必要
- △ = 日付ほぼ無し
- × = HTTPエラー/接続失敗/robots.txtでDisallow

### 追加調査で解決したもの(バスケ3チーム・実装済み)

当初は「直近数試合しか出ない」と判断していたが、URLのクエリを調べ直して解決した。

| 競技 | チーム | 採用URL | 取得数 |
|---|---|---|---|
| バスケ | 横浜ビー・コルセアーズ | `b-corsairs.com/schedule/list/?year=2026&month=all` | 61 |
| バスケ | 川崎ブレイブサンダース | `kawasaki-bravethunders.com/schedule/list/?year=2026&month=all` | 61 |
| バスケ | 富士通レッドウェーブ | `sports.jp.fujitsu.com/redwave/pages/nextgames` + `/page/N` | 37 |

分かったこと:

- ビー・コルセアーズとブレイブサンダースは同じCMSの同じテンプレートで、`/schedule/list/` に
  `?year=<年>&month=all` を付けるとシーズン全体(2026年9月〜2027年5月)が1ページで返る。
  `/schedule/`(list無し)や `?scheduleMonth=N` ではクエリを変えても同じHTMLが返るため、
  当初は「直近数試合のみ」に見えていた。パーサーは2チームで共通化できる。
- 富士通レッドウェーブはWordPressで、「試合予定」が1ページ12件のページ送りになっている。
  4ページ目まで取得でき、5ページ目は404で終端が分かる。ホーム/アウェイ表記は無い。
- Wリーグ公式(wjbl.org)はJavaScript描画で初期HTMLに日程が無く、チーム別ページも404だった。

## 分かったこと

1. **リーグ公式サイトの方が良いソースになる場合がある**。卓球(tleague.jp)、ラグビー
   (league-one.jp)、ハンドボール(leagueh.jp)、野球(npb.jp)は、チーム公式サイトより
   リーグ公式サイトの方がまとまった日程を持っている。特にラグビーは
   チーム公式(canon-eagles.jp)が日付0件なのに対し、リーグ公式は90件。
2. **Next.js製でもサーバー側描画なら取得できる**。横浜FC・NECレッドロケッツ・
   jleague.jpはNext.js製だが、初期HTMLに日程が含まれていた。
   調査初期に「JSフレームワーク=取得不可」と判断したのは誤りだった
   (ページ先頭1500文字だけを見て判断していたため)。
3. **既定のページが直近数試合しか出さないことがある**。バスケ2チームは一見そう見えたが、
   実際には `/schedule/list/?year=<年>&month=all` でシーズン全体が返った。
   「件数が少ない=取得できない」と早合点せず、ページ内のリンクやクエリを確認する価値がある。
4. **競技によって取得方法が違う**。サッカー・卓球・ラグビー・ハンドボール・バレー・
   バスケ(B.LEAGUE)は1ページでシーズン分が取れる。野球は月別
   (`/schedule/2026/9`)、Wリーグはページ送り(`/page/N`)。

## 公式API・カレンダー配信について

Jリーグ・NPB・Bリーグ・リーグワンのいずれについても、認証不要で購読できる
公式のICS/APIは確認できなかった。Jリーグは公式サイトにカレンダー追加機能が
あるとの報道があるが、配信URLの仕組みは未確認。TimeTree公開カレンダーは
J1全60クラブ・NPB向けに提供されているが、アプリ外から自動取得する正規の手段が
確認できないため採用していない。

## 利用規約について(未解決)

`scripts/inspect-sources.mjs` は robots.txt の `User-agent: *` の Disallow を
機械的にチェックしており、上記で取得したページはいずれも Disallow 対象ではなかった。
ただし各サイトの利用規約(Terms of Service)本文はrobots.txtでは分からないため、
本格運用の前に人間による確認が必要。
